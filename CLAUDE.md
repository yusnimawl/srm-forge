## What this is

`srmcore` is the core engine (sub-project #1) of an in-house switched reluctance motor (SRM) design tool. It is a Python library with no UI and no server. The finished engine takes a radial SRM design and produces validated flux-linkage and torque maps. It has to be fast enough for an optimizer to call it.

The on/off axes are the old 80-point axis extended to 1.25 pitch at the same density (80 on x 116 off at 181 angles); the drive's flux tail runs past aligned. ## Architecture rules (enforced by tests)

`tests/test_import_rules.py` parses every source file and fails on forbidden imports (spec §3.2):

| Subpackage | May import (internal) |
|---|---|
| `model` | nothing |
| `materials`, `fields`, `topology` | model |
| `geometry` | model, topology |
| `mesh` | model, geometry |
| `physics` | model, materials, mesh |
| `solvers` / `post` | model, materials, physics, fields |
| `maps` | all of the above |
| `project` | model, maps |

- Only `geometry/` and `mesh/` may import `gmsh`. Only `solvers/` may import `skfem`, `ngsolve` or `netgen`. Top-level modules such as `srmcore/__init__.py` must not import any of `gmsh`, `skfem`, `ngsolve` or `netgen`.
- Layers exchange plain data: numpy arrays, frozen Pydantic models and frozen dataclasses. Never pass Gmsh or solver objects across a layer boundary.
- Everything is in SI units internally (metres, radians, amperes). The validator rejects values that look like millimetres, with rule `units`.

## Pipeline (M1)

`Design` (in `model/design.py`: frozen, `extra="forbid"`, schema-versioned) holds `RadialSRMParams`, `MeshSettings` and `RegionMaterials`. It flows through these steps:

1. **`model/validator.py`**: closed-form checks that run before meshing. They cover Lawrenson feasibility, fit, clearances, units and minimum web width. Errors raise `InputError`, which names the parameter and the rule. Warnings are returned.
2. **`topology/radial.py`**: builds a pure-Python 2D outline from `primitives.py` (lines, arcs, fillets). When `RadialSRMParams.iron` (`model/iron.py` `ImportedIron`, omitted from JSON when None) is set, the stator and rotor laminations come from imported loops instead (`topology/imported.py`: `parametric_iron`, `to_segments`/`from_segments`, `iron_from_loops`, `check_iron`, `iron_areas`; `build_outline` raises `InputError` on failing iron; refinement tag `iron_detail`). `topology/dxf_io.py` (the only `ezdxf` importer) has `write_dxf`, `read_loops` and `import_dxf`; `srmapp.sizing.estimates.active_mass` uses the imported iron areas. The outline includes the stator bore, the rotor boundary, coil sides and refinement features (`pole_tip`, `pole_root`). No Gmsh is involved at this stage. Fit failures are converted to `InputError`.
3. **`geometry/build.py`**: turns the outline into Gmsh OCC surfaces with named regions (iron, shaft, coil sides `coil_A1+`/`coil_A1-`, slot air, air-gap layers, band; imported iron adds the air regions `stator_hole_air` and `rotor_hole_air`). `geometry/session.py` initialises Gmsh once per process and gives each use a fresh, isolated model. Building a second mesh in the same process must produce an identical result.
4. **`mesh/static.py`**: meshes the stator and the rotor **once**, with the rotor at angle 0, and extracts `StaticMesh`. The iron mesh never changes afterwards, because later loss evaluation needs fixed iron nodes. `mesh/settings.py` resolves presets (`screening` knobs; `full` and `reference` are the same knobs at fixed `MeshSettings.scale`, 2^(-1/2) and 0.25) and the band pitch. `mesh/sizing.py` is the size field.
5. **`mesh/machine.py` `mesh_at_angle`**: rotates the rotor nodes and re-triangulates only the thin moving-band annulus. `band.py` zips two node rings that have the same uniform pitch. Angles are wrapped into [0, 2π). `snap_angle` snaps an angle to the band pitch.
6. **`mesh/quality.py`**: quality report and gate. A failure raises `MeshRejected`, which carries either a `MeshQualityReport` or a `BandRejection`.
7. **`mesh/api.py` `build_machine_mesh`**: the public entry point. It validates, builds the static mesh and quality-gates it at angle 0 and at half a band pitch.

## Solve pipeline (M2–M4a)

1. **`materials/`**: `load_material(name)` reads `materials/data/<name>.json`. `process_bh` checks units, adds the origin, applies the stacking factor, requires J = B − μ0·H to be non-decreasing, and builds a monotone Hermite H(B) with a C¹ tail towards Js. `library_law(name)` returns the cached `ReluctivityLaw`; conductors and air use `LinearLaw`/`VACUUM`.
2. **`physics/build.py` `machine_problem(mesh, design, currents)`**: assigns laws by `region_kind` through `RegionMaterials`, builds the connection matrix from `CoilInfo` (`physics/winding.py`), takes Dirichlet nodes from `outer_edges` and band info from the mesh. It never parses region names.
3. **`solvers/skfem_reference.py` `SkfemReference().solve(problem, initial=None)`**: P1, quadrature order 2, Newton with the consistent Jacobian, and both residual and ΔA < 1e-8. On failure it falls back to damped Newton, then a current ramp, then `NONCONVERGED`; it never raises. It returns a `FieldSolution` (`fields/solution.py`) with A, element B, ν and energies.
3b. **`solvers/ngsolve_adapter.py` `NgsolveAdapter().solve(problem, initial=None)`**: the same contract and Newton scheme as `SkfemReference`, with the tangent built as numpy element matrices (`physics.fem.tangent_element_matrices`) scattered into NGSolve's sparsity pattern, and NGSolve supplying the load and the umfpack factorisation. `tests/physics/test_tangent_kernel.py` checks the tangent against NGSolve's own assembly. The secant residual is `physics.fem.secant_residual` (numpy). ν, dν/dB² and J are element-constant order-0 L2 grid functions; the quadrature rule is pinned to `QUADRATURE_ORDER`. The Newton driver is a deliberate separate copy, so the cross-solver tests compare the converged solutions (A, energies, ψ, torque), which checks assembly and the linear solve indirectly; the numpy stiffness is checked in `tests/physics/test_p1_kernels.py`. NGSolve is the `[ngsolve]` optional extra; its tests use `importorskip`.
4. **`post/quantities.py`**: `flux_linkage`, `arkkio_torque` (band radii from the mesh; positive counter-clockwise), `virtual_work_torque` (nodal-force torque from a virtual rotation of the band nodes at fixed A; agrees with Arkkio to 0.02 % on the 8/6) and `saturation_report`. Phase A is aligned at θ = 0, and counter-clockwise motoring excites A → B → C → D. `incremental_inductance(problem, sensitivity)` returns L_inc = ∂ψ/∂i (H) from the converged tangent.
4b. **`solvers/*` `sensitivity(problem, a)`**: dA/di per circuit (nodes × circuits) from the tangent at A; both adapters implement it, the adapters are compared with each other, and L_inc is checked against central differences.
4c. **`post/end_winding.py`** `end_turn_inductance(...)`: analytic end-winding inductance of a coil (Grover partial inductances of the two end overhangs). `image_factor` runs from 1.0 (default, coil in free air, the lower bound) to 2.0 (iron image, the upper bound); reports use the midpoint 1.5. **`maps/end_winding.py`**: `coil_geometry`, `end_winding_inductance(machine, image_factor)` per phase, and `with_end_winding(result, l_end)`, which adds L_end·i to ψ (and the energies and L_inc) after the map. Torque is unchanged; the 2D map and its cache are never altered, and `build_map` does not apply it. 3D iron-end fringing is not modelled.
5. **`maps/point.py` `solve_point(static, design, angle, currents, solver, initial=None, keep_field=False, with_l_inc=False)`**: mesh_at_angle → machine_problem → solve → post, returning a frozen `PointResult` (ψ, Arkkio and virtual-work torque, W, W′, status, iterations, optional L_inc). L_inc is withheld unless the solve converged at full load.

## Map pipeline

1. **`maps/grids.py`**: `angle_grid` (dense at the pole corners, snapped to the band pitch, one rotor pole pitch) and `current_grid` (power law, dense at low current); `GRID_SIZES` gives the default (angles, currents) per fidelity preset: screening 40 × 8, full 48 × 20, reference 120 × 40.
2. **`maps/run.py` `run_map(static, design, angles, currents, solver_name, excited="A", workers=1, ...)`**: one job per point (each solved from A = 0, highest current first), then `apply_failure_policy` (isolated non-converged points are PCHIP-filled along current and flagged; the map fails with `MapFailed` above 2 % failed points or on a failure at the aligned angle, at zero current or at I_max). It validates `excited` (any phase of the machine; `aligned_angle` validates the letter) and the currents before making a solver. Cancellation returns a partial, unfilled result with `complete=False`.
3. **`maps/dataset.py`**: `provenance` hashes the design, the resolved mesh settings, grids, excitation, solver and srmcore version plus the material JSON bytes; `write_map`/`read_map` use HDF5; `cached_map`/`store_map` serve and store complete maps only, and treat foreign-schema files as misses.
4. **`maps/pool.py` `map_ordered`**: spawn `ProcessPoolExecutor`, results in item order, one retry of the unfinished items after a worker crash, then `WorkerCrashed`. `workers <= 1` runs in-process, through the same `_init_worker`. Workers run single-threaded numerics (`OMP/OPENBLAS/MKL_NUM_THREADS=1`, `make_solver(name, threads=1)`).
5. **`maps/api.py` `build_map(design, i_max, solver="ngsolve", excited="A", workers=None, n_angles, n_currents, cache_dir, progress, cancel)`**: grids, provenance, cache lookup, mesh built once in the parent, `run_map`, cache store. `workers=None` means half the logical CPUs.

## Map products

1. **`maps/tables.py`**: `angle_spline`, `dpsi_dtheta`, and `drive_tables` (`DriveTables`: inverse i(θ,ψ) and T(θ,ψ) on a saturation-graded ψ grid, flat, monotone, round-trip checked).
2. **`maps/results.py`**: `key_numbers` (`KeyNumbers`: La and Lu as secant values at 5 % of I_max, peak torque, ψ_max), `inductance_curves`. `grids.aligned_angle` gives each phase's aligned angle.
3. **`maps/checks.py`**: the cheap §7.3 checks (`Check`), `analyse_map` returning a `MapReport`. Energy checks warn instead of fail below 16 angles. Limits are provisional (spec §11).
4. **`maps/export.py`**: `export_csv`, `export_mat`.
5. **`maps/overlap.py`** with `api.build_overlap_map`: overlap map, coupling and reciprocity checks; any non-converged point in a complete overlap map raises `MapFailed`.
6. **`maps/fem_checks.py`**: held-out interpolation and band-radius independence (`full`/`reference` only). **`maps/fidelity.py`**: `fidelity_check` (screening vs full).
7. The map and HDF5 dataset also hold energy, L_inc (excited column), per-pole force vectors (`post/forces.py`) and `b_peak` (area-weighted 99.9th percentile of iron |B|, `point.B_PEAK_QUANTILE`; the `iron_b_peak` check compares it with the last stacked B-H point). Every phase can be excited; its angle grid is the phase-A grid shifted by that phase's aligned angle. The pool runs one job per map point, largest current first. `pool.default_workers` is shared by the API and the checks.
8. `tests/maps/test_goldens.py` (slow) compares the 8/6 screening key numbers and check statuses with `goldens_8_6.json`; the regeneration command is in its docstring.
9. **`maps/validation.py`** `em_validate(design, result, solver="ngsolve", workers=None)` returns `EmValidation(label, checks, budget, engine_version, material_grades)`. The label ("2D-verified") needs every check to pass: `engine_version` (in `VALIDATED_VERSIONS`, `("0.4.0",)`; the validation report gates adding a version), `preset` (the map's preset equals the design's, and is `full` or `reference`), `map_identity` (the map's design hash, `maps.identity.design_hash`, equals the design's), `no_filled_points`, `map_matches_design` (the peak-torque key point solved on the design's mesh equals the map's value within 0.1 %), `point_convergence_psi` / `_torque` (4 key points on `full` vs `reference`: ψ 0.5 %, torque 1 % of peak), the `fem_checks` (including `held_out_converged`, which warns when a held-out solve was skipped), `material_grade` and `budget_finite`. `UncertaintyBudget` has worst-case rows (mesh, material = Js ±2 % plus grade allowance A 0 / B 3 / C 10 %, end effect at image factors 1 and 2, digitisation via `SoftMagneticMaterial.digitisation_error`) relative to the end-winding-corrected key numbers beside the 2D values (the mesh and material rows are rescaled by 2D value / corrected value). When the B-H data already exceed Js − 2 % (M19, steel_1010) only +2 % is used and the note says so. It runs up to 16 sequential solves and stores nothing.

Analytic test problems (the current-sheet toroid and MMS on the unit square) live in `tests/fem_fixtures.py`. `tests/team24_fixture.py` builds the TEAM Problem 24 rig as a `Magnetostatic2D`; the comparison is in `docs/m5b-team24-results.md` and the slow test in `tests/validation/test_team24.py`. `tests/femm_machines.py` defines the FEMM comparison machines and points; fixtures are in `tests/validation/fixtures/`, the slow test is `tests/validation/test_femm.py`. `tests/emdlab_machine.py` defines the EMDLAB paper's 8/6 (material `M530_50A`, a non-magnetic shaft, a 1392-division band so the 30 reference angles are band nodes); the slow test `tests/validation/test_emdlab.py` compares it with ANSYS Maxwell and EMDLAB at 3.6 A (`tests/validation/fixtures/emdlab_8_6/`, results `docs/emdlab-results.md`: torque within 2.99 % of peak against Maxwell and 3.78 % against EMDLAB). `tests/solvers/test_cross_solver.py` compares the two solvers at 1e-4. Test file basenames must be unique, because `tests/` has no `__init__.py`.

## Tests

- `tests/conftest.py` provides the reference designs as factories `make_8_6`, `make_12_8` and `make_24_16`. Each accepts `**overrides`. The same designs are available as fixtures (`srm_8_6`, …, and the parametrized `reference_design`). `pythonpath = ["tests"]`, so tests can `from conftest import make_8_6`.

## Conventions

- Keep comments free of task or plan history. Comments should explain the code as it is now.
- Open owner decisions are tracked in spec §10; decisions go in spec §11. `self_starting` is a hard error for user designs; only validation reference machines may build inside `model.validator.waive_rules("self_starting")`. The minimum web width is max(1 mm, 2 × lamination thickness).

## Losses (R3)

1. **`materials/loss.py`**: `fit_loss` fits Bertotti k_h, alpha, k_e to a loss table (k_c computed from conductivity, thickness and density); the fit is valid up to 1.3 T (10JNEX900 `b_range` 0.2 to 1.3 T), and `waveform_loss` reports the high-B and low-B shares of the loss outside the fitted range. `loss_model(name)` raises `MissingLossData` for a material without a table (10JNEX900 has one; the M19 loss data are test-only, `tests/materials/m19_loss_fixture.py`).
2. **`post/iron_loss.py`** `waveform_loss`: per-element loss of a B(t) waveform over one period (hysteresis from reversals with the DC-bias factor, classical and excess from dB/dt), W/kg.
2b. **`post/cut_edge.py`** `CUT_PROCESSES` (wedm, punching, laser: width coefficient a with range, band width delta), `cut_edges`, `band_fraction` (share of each element within delta of a cut edge) and `edge_multiplier` (1 + a/(2 delta) x fraction, over `B0`); `srmapp.losses.stroke_losses(cut_process=...)` applies it to hysteresis plus excess and returns `cut_edge_rel` and per-region `cut_edge_factor`.
3. **`maps/stroke.py`**: `stroke_fields` solves every phase at once over one rotor pole pitch (`stroke_angles`, default 60 angles snapped to the band pitch) and caches B under `<cache_dir>/strokes/`; `iron_waveforms` gives the stator waveforms over one pitch and the rotor waveforms over K pitches (period K x tau, found by `rotor_pitches`; rotor elements are located by rotated centroid).
4. **`srmapp/copper.py`** `ac_copper_loss`: skin and proximity loss per current harmonic (wire mode only); proximity uses harmonics per coil element and per component, area-weighted mean of |Bx,h|^2 + |By,h|^2. **`srmapp/losses.py`**: `efficiency_map` (6 speeds x 5 torque levels; per point the least-copper stroke from `min_copper_stroke`, its fields on the reference-turns design, iron and AC copper loss; `iron_uncertainty_rel` = fit error × (1 + high_b_share) + grade allowance (A 0, B 10, C 25 %) + `ANGLE_CONVERGENCE_REL`, a placeholder until the slow convergence test has measured it), `stroke_losses` (the iron loss of a given stroke, with an optional loss-model override), `b_waveform`.
5. `Requirements.winding_temperature_c` (default 120 degC) sets the resistance and AC-loss temperature. `Evaluation.srmapp_version` records the srmapp version that made an evaluation.
6. Web: job kind `losses` (steps queued/strokes/fields/losses/saved, main lane); routes `POST/GET /api/cases/{id}/losses`, `GET .../losses/estimate`, `GET .../losses/b?point&x&y`; the result is stored as result kind `losses`; the Losses tab is `web/src/components/analysis/LossesTab.tsx`. The cache route counts and clears `strokes/*.npz` with the fields. Friction and windage are excluded and the chips say so.

## Control SIL (R8a)

`src/srmsil` (own version, 0.9.0; needs the `sil` extra, `ziglang==0.16.0`, which the `web` extra includes) runs portable controller C against a simulated SRM drive built from an evaluated case. Spec: `docs/superpowers/specs/2026-10-19-r8a-control-sil-design.md`.

- Layout: `c/srm_hal.h` (HAL), `c/srm_ctrl.h` (controller contract), `c/sim/` (motor, converter, sensors, scheduler, trace buffers, ctypes entry points; all C), `c/controllers/` (`hysteresis`, `pwm_current`, `tsf`, shared `common/srm_ref.[ch]`, one README each); `build.py` (zig compile, host library and Cortex-M7 target check, cache keyed by source hash), `tables.py` (`MotorData` from an evaluation, `srm_motor_tables.h` writer), `scenario.py` (`Scenario`, `ConverterSettings`, `SensorSettings`, `AdcSettings`; `MAX_STEPS` 50 000 000), `run.py` (`run(motor, controller, scenario, cache_dir=...)` returns `SimResult`; `SimError` carries the compiler log).
- HAL (`srm_hal_t`, filled by the driver): `set_switches`, `set_pwm`, `adc_read`, `encoder_count` (single turn, [0, cpr)), `resolver_sincos`, `micros`, `vbus_volts`, plus the constants `n_phases`, `pwm_hz`, `isr_hz`, `adc_bits`, `adc_amps_per_count`, `adc_offset_counts`, `encoder_cpr`, `adc_volts_per_count` and `adc_volt_offset_counts` (R8b; `adc_read` channels q..2q-1 are the phase voltages, `adc_volts_per_count` 0 means none). Controller code and these two headers use no dynamic allocation and no OS calls; controller maths is `float`, the sim core may use `double`.
- Controller contract: `ctrl_param(name, value)` (0 accepted, -1 unknown, -2 known but not changeable while running; callable before `ctrl_init` and at any time after), `ctrl_init(hal)`, `ctrl_command(mode, value)` (torque N·m or speed rad/s), `ctrl_isr()` (at `isr_hz`), `ctrl_slow()` (1 kHz). A folder is every `.c` file in it; a missing `ctrl_isr` or a compile error is a `SimError` with the log.
- Reference controllers take their parameters through `ctrl_param` (listed by `GET /api/control/controllers`, `run.PARAMS`), including `resolver_pole_pairs` (p must divide N_r). Speed PI: kp = J·ω_c, ki = kp·ω_c/16, default gains tuned for J ≈ 1e-3 kg·m². The hysteresis command is the per-phase torque at the window centre.
- Phase k is aligned at k·ε, ε = 2π/(q·N_r); motoring is counter-clockwise. The maps hold one excited phase, so there is no mutual coupling. Currents beyond the map extrapolate linearly in ψ and `SimSummary.beyond_map_fraction` reports it. `compute_delay` defaults to one ISR period.
- Isolation: controller C is never loaded into the server or test process; `run.run` loads it in a spawned child (a segfault, endless loop or rejected parameter gives a `SimError`). A custom folder runs only on a loopback host, enforced at the route (403) and again where the job runs.
- Web: job kind `control` on the main lane (steps queued, compile, simulate, saved; results are npz in `<cache_dir>/sil/runs/`, counted and cleared with the cache). Routes: `POST /api/cases/{id}/control`, `GET /api/jobs/{id}/control?n_px=`, `GET /api/cases/{id}/control/header` (download `srm_motor_tables.h`), `POST /api/control/target-check`, `GET /api/control/controllers`. The Control tab (`web/src/components/analysis/ControlTab.tsx`, `ControlScopes.tsx`) is on evaluated cases.
- Tests: `tests/sil/` (names `test_sil_*.py`, helpers in `sil_fixtures.py` with the analytic motor); they compile with zig, so they need `ziglang` installed. The example is `examples/control_sil.py`.

## Control HIL (R8b)

`hil/` (PlatformIO firmware, not a Python package) and `src/srmsil/hil` run the owner's controller C unchanged on a Nucleo-H723ZG against a Teensy 4.1 that emulates the SRM drive in real time from an evaluated case. Spec `docs/superpowers/specs/2026-10-20-r8b-control-hil-design.md` (§16 lists the decisions made during implementation, with dates), wiring `docs/r8b-hil-wiring.md`, bench results `docs/r8b-hil-results.md`. Implemented on branch `r8b-hil-spec`, not merged; versions not bumped.

- Layout: `hil/common` (`hil_proto.h`: COBS-framed packets with CRC-16 shared by firmware and Python; `hil_chips`: AD7606, AD2S1210 and MCP492x coding), `hil/emulator` (Teensy: step loop, gate-edge capture, AD7606 and AD2S1210 slaves, DAC, encoder, USB), `hil/controller` (Nucleo: `srm_hal_stm32.c`, TIM1/TIM8 AHB PWM, AD7606, internal ADC, encoder and AD2S1210 drivers, ST-LINK serial), `hil/scripts/add_sources.py` (adds the owner folders, the generated headers and the mode macros). The plant (`src/srmsil/c/plant`: state, Heun step, gate averaging, AHB voltage, sensors) is shared by the PC SIL and the emulator (`srm_table_t` and `srm_real_t` are `float` in the emulator build, `double` on the PC); `src/srmsil/c/emu/srm_emu.c` with `srmsil.emumodel` is the PC build of the emulator model that CI compares with the SIL at 1 %. Python `src/srmsil/hil/`: `proto`, `transport` (pyserial, imported lazily; boards found by USB VID/PID, Teensy 0x16C0 and ST-LINK 0x0483, never by COM number), `config` (`HilModes`, `write_hil_config`, sensor chain and rate checks), `build` (`build_and_flash`, `firmware_hash`, `check_sources`), `session` (`HilSession`, `run_hil`, `check_build`, `capture_health`), `compare` (`matched_scenario`, `match_plan`, `compare`), `fake` (a fake rig for tests and the web layer). Web: `srmweb/hil.py` (`HilManager`) and the HIL routes in `api.py`; `web/src/components/analysis/HilPanel.tsx` and `web/src/lib/hil.ts`. Layering as R8a: `srmsil` never imports `srmweb`, firmware never imports Python.
- Modes are build-time and never a rewire: `current_sense` `ad7606` or `internal` (DACs drive the Nucleo's ADC pins; `dac` `mcp4922x2` or `mcp4921x4`), `position` `encoder`, `ad2s1210` or `both` (`SRM_HIL_MODES`). The session reads both boards' BUILD_INFO and refuses a session whose modes or firmware hashes differ from the flashed build or whose sources changed since the flash. `internal` mode is compiled in CI but was not benched (no DACs).
- Setup: `hil\setup.bat` (or `sh hil/setup.sh`) creates `hil/.runtime` (git-ignored; PlatformIO 6.2.0, the Teensy and STM32 platforms in `hil/.runtime/core`); nothing is installed outside it and the shared `.venv` is never changed. The extra `hil` is `pyserial==3.5`. The build hash covers every file under `hil/` (comments and READMEs too) and the `.c`/`.h` files of the plant and the controller folders, so editing any of them needs a reflash before a session opens. `.github/workflows/hil.yml` compiles both environments in all six sense x position modes when `hil/**`, `src/srmsil/c/**` or `src/srmsil/hil/**` change.
- Emulator facts: 912 MHz (heatsink; a run stops above 85 degC; 1008 MHz fails timing), 6 us step (`HIL_EMU_STEP_NS`, one constant, mirrored as `proto.EMU_STEP_NS`/`EMU_DT`), float plant, tables (180 x 192) uploaded at session start so the firmware does not depend on the case, gate edges stamped with the cycle counter, AD7606 BUSY by XBAR and QTIMER4. A self-check of the gate averager runs at every START (`HIL_ERROR` on a wrong hash). Captures are buffered in the 8192-sample RAM ring (49 ms, 36 B per sample, the default capture length); full-rate streaming of longer captures does not keep up and is unsupported. Any step overrun or dropped packet makes the run `valid = false`; a step max over 80 % of dt is a warning only. About 3 % of captures lose a packet (cause open) and are marked invalid.
- Controller side: `isr_hz` must be `pwm_hz / k`, k odd (the sample instant is the carrier centre); encoder CPR x rev/s <= 400 000; `ctrl_param` works live (0, -1 unknown, -2 not while running; per-controller lists in the controller READMEs); a `ctrl_isr` that does not return is abandoned and stops the run; the controller board is reset when a session is configured; the emulator measures the controller's real clock from its sample trigger (the Nucleo's HSE runs about 1 % fast) and the SIL uses it.
- Matched SIL and comparison (`compare.py`): `matched_scenario` sets `controller_clock` to the measured ratio, `compute_delay` to one true ISR period, `sensors.delay` = measured latency - dt/2 with `delay_jitter` = dt (`SensorSettings`), and the HIL chain's `AdcSettings`; `configure` refuses scenario fields the HIL does not emulate (`adc.offset_error`, `adc.gain_error`, `adc.noise`, `adc.rc_tau`, `sensors.delay`, `sensors.delay_jitter`, `param_steps`). `compare` passes when the run is valid, no current sample clipped, the SIL covers the window, mean torque and RMS current are within 3 % and the median per-stroke ripple within 5 points (at least 3 complete strokes each side; whole-window ripples are information only). A live capture's SIL starts `SETTLE_S` (0.2 s) before the window at fixed speed and at Start when dynamic; parameter or command changes inside that span give `passed` false with the reason.
- Web: one live session, loopback host only (routes and session both enforce it). Job kind `hil_flash` on the main lane (steps queued, build, flash, saved; `POST /api/cases/{id}/hil/flash`, log and hash at `GET /api/jobs/{id}/hil-flash`). Session routes `POST/DELETE /api/hil/session`, `GET /api/hil/session/events` (SSE, 20 Hz), `POST /api/hil/session/param|command|start|stop|capture`; captures are npz in `<cache_dir>/sil/hil/` (counted and cleared with the cache), `GET /api/hil/captures/{id}` (traces, with the matched SIL once compared) and `.../compare`. The Control tab has a SIL / HIL switch; HIL mode shows the mode selectors, Build & Flash with its log, board status, Start/Stop, live numbers and warnings, parameter rows (sent on blur or Enter; free-form name = value rows for custom controllers), the command, Capture, the overlay scopes and the comparison.
- Tests: `tests/hil/` (names `test_hil_*.py`; C test sources in `tests/hil/c`; they compile C with zig; `tests/sil` is on pytest's `pythonpath`; the PlatformIO build test is skipped without `hil/.runtime`), including `test_hil_web.py` on the fake rig; vitest `HilPanel.test.tsx` and `hil.test.ts`. The bench items run with boards attached and are recorded in `docs/r8b-hil-results.md`.
