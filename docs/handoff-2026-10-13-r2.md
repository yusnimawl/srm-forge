## Questions to settle in the brainstorm

- Where the imported outline enters the pipeline. Today `topology/radial.py` builds a pure-Python outline from `primitives.py` and `geometry/build.py` turns it into Gmsh OCC surfaces. An import should probably produce the same outline structure (or a parallel one) so `geometry`, `mesh` and everything after stay unchanged.
- What may be edited: iron only (stator and rotor laminations), or coils too. Coils carry the winding (`CoilInfo`, connection matrix), so editing them is a much bigger change.
- The moving band needs rotor and stator separable by the air-gap circle, and the iron mesh must stay fixed (loss evaluation later). Which edits break that, and how the import check says so.
- Cache and map identity for an imported shape (`maps.identity.design_hash`, `maps.dataset.provenance` hash the parametric design today).
- How a case holds an imported shape (`CaseInputs`, setup files, the web case flow) and how the before/after compare is shown.
- DXF library: an installed dependency or a new one (ezdxf is the usual choice; licence MIT). Gmsh can also read DXF via OCC import, but region mapping is easier from parsed entities.
- Units in DXF files (mm in CAD, SI inside; the validator rejects millimetre-looking values).
