# R2: DXF round trip

Merged 2026-10-16, PR not recorded (branch merge d12220a). Versions after the merge: srmcore 0.5.0, srmweb and `web/` 0.5.0.
Spec `docs/superpowers/specs/2026-10-15-r2-dxf-round-trip-design.md`. Plan `docs/superpowers/plans/2026-10-15-r2-dxf-round-trip.md`. Detailed results `docs/r2-dxf-results.md`.

## Goal

Export a case's laminations as DXF, edit the iron in CAD, import it, map it and compare before and after. Done when this works end to end on the 8/6.

## What shipped

- `ImportedIron` model and `Design.iron` (omitted from the JSON when None, so every old design hash and cache stays valid).
- `topology/dxf_io.py` (`write_dxf`, `read_loops`, `import_dxf`) and `topology/imported.py` (iron checks: closed loops, gap circle, minimum web, repeat every pole pitch).
- Meshing of imported iron through an extended `RadialOutline`. Holes become the air regions `stator_hole_air` and `rotor_hole_air`.
- `srmapp.sizing.estimates.active_mass` uses the imported iron area.
- Routes `GET/POST /api/cases/{id}/dxf` and `GET /api/cases/{id}/compare`. In the UI: the Export menu item "Geometry (DXF)", an Import DXF button, an import dialog and the before/after table.
- Onshape reader fixes on 2026-10-18 (d7cae97).

## Decisions

- 2026-10-15, owner: import the iron only. Coils, winding, band radii and end-winding geometry stay parametric.
- 2026-10-15, owner: edits repeat every pole pitch. Anything else is refused with the rule and an example fix.
- 2026-10-15, owner: regions come from geometry, not DXF layers (Onshape has no layers).
- 2026-10-15, owner: the imported shape is an extended `RadialOutline`. Boolean diffs were rejected (near-coincident edges give slivers).

## Open after this step

- The untrimmed Onshape export is still refused with two open loops at the notch (by design).
- srmcore 0.5.0 was never in `VALIDATED_VERSIONS`. 0.7.0 was validated on 2026-10-31.
- Per-phase maps for non-repeating edits are out of scope.
