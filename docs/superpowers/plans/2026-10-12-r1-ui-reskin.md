# R1 UI reskin and label rename Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the web app to the black Graphite theme with no blue anywhere, rename the "EM-validated" label to "2D-verified", and show the assumed `j_limit` on every result.

**Architecture:** One `:root` token block in `web/src/index.css` drives shadcn and every page (dark only). Data colours live in three places (`lib/inferno.ts`, `LINE_COLORS`/`LINE_DASHES` in `lib/analysis.ts`, one Plotly theme in `components/PlotlyPlot.tsx`); a Vitest guard fails on blue. The label is one constant in `srmcore.maps.validation`; the assumed `j_limit` travels as a new `Evaluation.j_limit` field through `EvaluationOut` to a chip.

**Tech Stack:** React 19, Vite, TypeScript, Tailwind v4, shadcn (Base UI), Plotly, WebGL2; Python 3.12+, FastAPI, Pydantic.

**Spec:** `docs/superpowers/specs/2026-10-12-r1-ui-reskin-design.md` (theme values §3, data colours §4, pages §5, label and chips §6, guards §7). Mockup: `docs/r1-mockups/case-page.html`, theme "Graphite".

## Global Constraints

- No blue: no Tailwind `blue-`, `sky-`, `indigo-`, `cyan-` classes; no colour literal with hue 190–250° and saturation above 15 % anywhere in `web/src` except `api/schema.ts`.
- Dark only: no light theme, no `.dark` variant, no `dark:` classes, no theme toggle.
- Colours come from tokens (`var(--…)` or Tailwind token classes); hex literals only in `index.css`, `lib/inferno.ts`, `lib/analysis.ts` (`LINE_COLORS`) and `lib/fieldGl.ts` (line RGBA).
- Fonts: Geist and Geist Mono (Google Fonts); numbers and inputs in Geist Mono with `font-variant-numeric: tabular-nums`.
- Layout, routes, data, behaviour and accessibility attributes (roles, aria labels, 44 px touch targets via `min-h-11`) stay as they are.
- srmcore stays version 0.4.0 (spec §2). srmweb and `web/` go to 0.4.0 in Task 7.
- `web/src/api/schema.ts` is generated: `python -m srmweb.openapi web/openapi.json; cd web; npm run gen:api`. Never edit it by hand.
- Comments describe the code as it is now, with no task or plan history.
- Edit files only with the Edit/Write tools, never with shell heredocs or `sed`.

## Review Focus

1. **Evaluations stored before this change** have no `j_limit`: the chip reads "j_limit not recorded", never "NaN" or "undefined" (Task 1 API test, Task 4 `jLimitChip(null)` test).
2. **Validations stored with the old label "EM-validated"** still count as verified and show "2D-verified" (Task 4 `caseStatus` test with `validated: true`; the API keeps `validated = bool(label)`).
3. **Inferno's black end against the black page:** region outlines must stay visible where |B| ≈ 0 (Task 3 sets `OUTLINE` to grey; the fieldGl test pins it).
4. **Phone width (375 px):** chips wrap, the KPI strip drops to two columns, no horizontal page scroll (Task 5 and 6 check at 375 px).
5. **Library defaults that carry their own colours:** Sonner toasts, Plotly hover labels, the Plotly mode bar, Base UI select popovers and focus rings must show Graphite, not library blue (Task 2 sets the toaster to dark, Task 3 sets `hoverlabel` and `modebar` in the Plotly theme; Task 6 opens a select and a toast for the screenshot).
