# srmbench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `bench/` folder whose `run.bat` / `run.sh` set up a pinned private environment, benchmark the real SRM engine in three tiers, write a result JSON, and rebuild a cross-machine comparison README.

**Architecture:** Shell bootstrap (uv → Python 3.12 → venv from a hashed lock → editable srmcore from the checkout) hands over to a Python package `bench/srmbench`. The package is split by responsibility: platform checks, machine info, the measured steps, the tier orchestration, projections, the result file, the README/charts, git publishing, and the CLI. Everything installed lives in `bench/.runtime/`.

**Tech Stack:** Windows batch, POSIX sh, uv 0.12.21, Python 3.12, srmcore/srmapp (NGSolve, Gmsh), psutil, py-cpuinfo, matplotlib, pytest.

**Spec:** `docs/superpowers/specs/2026-10-14-srmbench-design.md`

## Global Constraints

- Supported: Windows 10 build ≥ 17134 / 11 on x64 (`AMD64`); Linux `x86_64` with glibc ≥ 2.28. Refused: ARM (any OS), musl, 32-bit, other OSes. Refusal exit code 2.
- RAM minimum (total, accepted at ≥ 0.9 × the figure to allow reserved memory): quick 4 GB, standard 4 GB, long 8 GB. Free disk in `bench/.runtime/`'s drive ≥ 2 GB. Logical CPUs ≥ 2.
- uv pinned to 0.12.21. SHA-256: `uv-x86_64-pc-windows-msvc.zip` `5d223efa0bf00208c3853246af09420419dfbd352536aa6bb8163d6170e23890`; `uv-x86_64-unknown-linux-gnu.tar.gz` `23f02075b652bb1df64178cfae41b5caf160822e720e2663568f3f5d63bc52c0`. URL `https://github.com/astral-sh/uv/releases/download/0.12.21/<archive>`.
- Python 3.12, uv-managed only (`--python-preference only-managed`). `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR` and the venv are under `bench/.runtime/`.
- `BENCH_VERSION = "1.0"`, result `schema = "srmbench-result"`.
- Designs `srmapp.references.make_8_6()` / `make_12_8()`; `I_MAX = {"8_6": 20.0, "12_8": 10.0}`; solver `"ngsolve"`; cold runs (`cache_dir=None`).
- Labels: `^[a-z0-9-]{1,40}$`.
- No user name, home path, hostname or IP in result files (the label default may be derived from the hostname, but only the label is stored).
- No blue in charts: no colour with hue 190–250° and saturation > 15 %. Chart palette: reference `#8a8a8a`, others `#e8b04a`; multi-series lines use `["#ededed", "#e8b04a", "#9bd88a", "#e07fb5", "#f2716b", "#c3a6f0", "#8a8a8a"]` with dashes `["solid", "dashed", "dotted", "dashdot", (0, (8, 3)), (0, (8, 3, 2, 3)), "solid"]`; text and axes `#8a8a8a`; transparent background.
- Comments describe the code as it is, not the plan or task history.
- srmbench never imports `tests/`; nothing under `src/` imports srmbench.
- Bench tests live in `bench/tests/` and run with `bench/.runtime/venv` python: `python -m pytest -c bench/pytest.ini bench/tests` (from the repo root). The repo's own fast suite must still pass (`python -m pytest -m "not slow"` with the repo `.venv`).

## Review Focus

1. A second run on the same machine (venv present, nothing changed) must skip download and install and start the benchmark within seconds; a changed `requirements.lock` or `pyproject.toml` must reinstall. → Task 1 manual check and a stamp test in Task 1.
2. `run.sh` checked out on Windows with `core.autocrlf=true` must still have LF endings and the executable bit, or Linux fails with `/bin/sh^M`. → `.gitattributes` and `git update-index --chmod=+x` in Task 1; Task 7 CI runs it on Ubuntu.
3. A machine with more cores than RAM allows (e.g. 32 threads, 8 GB) must cap workers instead of paging or dying. → `max_workers` tests in Task 2; the tier runner applies the cap in Task 4.
4. Results from an older `bench_version`, a machine with only a quick result (no scaling data), or no reference-machine result must still render a README without errors. → report tests in Task 5.
5. Git publish on a machine with no git, no remote, a dirty tree or a rejected push must keep the result file and exit 0. → publish tests in Task 6.

**Files:**
- Create: `bench/srmbench/workload.py`, `bench/srmbench/monitor.py`, `bench/srmbench/reference/goldens_8_6.json` (byte copy of `tests/maps/goldens_8_6.json`), `bench/srmbench/reference/points_8_6.json` (generated, Step 5), `bench/tests/test_workload.py`, `bench/tests/test_monitor.py`

**Interfaces:**
- Consumes: srmcore/srmapp as listed in spec §4.
- Produces (all return plain JSON-able dicts; times in seconds):
  - `workload.I_MAX`, `workload.design(name: str, preset: str) -> Design` (`name` in `"8_6"`, `"12_8"`).
  - `workload.static_mesh(design) -> tuple[StaticMesh, dict]`, dict `{"seconds", "nodes"}`.
  - `workload.single_solves(static, design, n: int) -> dict` `{"samples": [...], "median": float}` — n cold `solve_point` calls at the aligned angle, phase A at `I_MAX`, each with a fresh `make_solver("ngsolve", threads=1)`.
  - `workload.reference_points(static, design) -> list[dict]` — 3 points `{"angle": rad, "current": A, "psi": Wb, "torque": N·m}` at aligned, mid and unaligned (`aligned_angle`, + τ/4, + τ/2 with τ = 2π/Nr), each snapped with `srmcore.mesh.band.snap_angle(angle, divisions)[0]`, divisions from `resolve_mesh_settings(design.machine, design.mesh).band_divisions`; psi is phase A (`psi[0]`), torque `torque_arkkio`.
  - `workload.check_points(got: list[dict], ref: dict, srmcore_version: str) -> dict` `{"status": "pass"|"fail"|"not checked", "details": [str]}`; `not checked` when `ref["srmcore"] != srmcore_version`; a value passes when `|got − want| ≤ 1e-4 × max(|want|, 0.1)`.
  - `workload.batch_grid(design, workers: int) -> tuple[np.ndarray, np.ndarray]` — `angle_grid(machine, divisions, 2 * workers, aligned=0.0)` and `np.array([I_MAX/2, I_MAX])` for the design.
  - `workload.time_batch(static, design, workers: int) -> dict` `{"workers", "points", "seconds", "per_min", "peak_ram_gb"}` — `run_map(static, design, angles, currents, solver_name="ngsolve", workers=workers)` under `monitor.WorkerRam`; `points = len(angles) * len(currents)`; `per_min = points / seconds * 60`.
  - `workload.grid_points(design) -> int` — `len(angle_grid(...GRID_SIZES[preset][0]...)) * len(current_grid(I_MAX, GRID_SIZES[preset][1]))` for the design's preset.
  - `workload.map_run(design, workers: int, goldens: dict | None) -> dict` `{"seconds", "points", "key_numbers", "statuses", "correctness"}` — `build_map(design, I_MAX, workers=workers)` + `analyse_map`; correctness against goldens (key numbers rel 1e-3, statuses equal) when given, else `"not checked"`.
  - `workload.extras_run(design, result, workers: int) -> dict` `{"seconds"}` — `build_overlap_map` + `fem_checks`.
  - `workload.sustained(static, design, workers: int, minutes: float, clock=time.monotonic) -> dict` `{"batches": [{"t", "per_min"}], "throttle_pct": float}` — repeat `time_batch` until `minutes` elapsed; throttle = (mean of the last 20 % of batches / mean of the first 20 % − 1) × 100 (at least one batch each; 0.0 with fewer than 2 batches).
  - `monitor.WorkerRam` context manager: a daemon thread samples every 0.5 s all descendants of the current process (`psutil.Process().children(recursive=True)`) plus the current process when `workers == 1`; `.peak_gb` = the largest single-process RSS seen (on Windows also `memory_info().peak_wset`); tolerates processes vanishing between samples.
- Generation command (also used in Step 5): `python -m srmbench.workload make-reference` writes `reference/points_8_6.json` = `{"srmcore": <version>, "points": reference_points(...)}` for the 8/6 `screening`.

### Task 4: Tiers, projections, result file

**Files:**
- Create: `bench/srmbench/tiers.py`, `bench/srmbench/projections.py`, `bench/srmbench/result.py`, `bench/tests/test_projections.py`, `bench/tests/test_result.py`, `bench/tests/test_tiers.py`

**Interfaces:**
- Consumes: Task 2 (`machine_info`, `package_versions`, `lock_hash`, `max_workers`, `Platform`), Task 3 (all `workload` functions).
- Produces:
  - `result.Result` (dataclass): `schema`, `bench_version`, `tier`, `label`, `started`, `finished` (ISO 8601 with offset, `datetime.now().astimezone().isoformat(timespec="seconds")`), `status` (`"complete"`), `machine: dict`, `versions: dict`, `lock_hash: str`, `steps: dict`, `summary: dict`, `warnings: list[str]`.
  - `result.validate_label(s: str) -> str` (raises `ValueError` with the rule).
  - `result.write_result(r: Result, results_dir: Path) -> Path` → `results_dir/<label>/<YYYY-MM-DD>T<HHMM>-<tier>.json` from `started`, UTF-8, `sort_keys=True`, `indent=1`; adds `-2`, `-3` … when the name exists.
