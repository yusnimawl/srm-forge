# R3 Losses and Drive Tail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Efficiency at any operating point of an evaluated case: copper loss (DC at a winding temperature, AC in wire mode), iron loss from B(t) in every iron element along the real stroke, a drive model whose flux tail may run past aligned, and an efficiency map in a `losses` web job.

**Architecture:** srmcore gains material loss data with a Bertotti fit (`materials/loss.py`), a waveform iron-loss kernel (`post/iron_loss.py`) and a stroke field runner (`maps/stroke.py`) that solves all phases together on the fixed iron mesh. srmapp gains the drive tail, the minimum-copper stroke for a given torque, AC copper loss and `losses.efficiency_map`. srmweb runs it as job kind `losses` and the web app shows a Losses tab.

**Tech Stack:** Python 3.12+, numpy, scipy (Bessel functions, least squares), NGSolve via the existing adapters, FastAPI, React 19 + TypeScript + Plotly, vitest.

**Spec:** `docs/superpowers/specs/2026-10-18-r3-losses-design.md`

## Global Constraints

- Import rules (`tests/test_import_rules.py`): `materials` imports only `model`; `post` imports model, materials, physics, fields; `maps` may import all of srmcore. No gmsh/ngsolve/netgen/skfem outside their layers. `srmapp` never imported by `srmcore`; `srmweb` never imports gmsh, ngsolve, netgen, skfem.
- SI units everywhere internally (T, Hz, W, m, rad, A). W/kg only in material JSON and the loss model coefficients.
- Bertotti per unit mass for a sinusoid of peak B at f: p = k_h·f·B^α + k_c·(f·B)² + k_e·(f·B)^1.5, with k_c = π²·σ·d²/(6·ρ_m) computed (σ conductivity S/m, d thickness m, ρ_m density kg/m³), never fitted.
- Waveform loss per unit mass over one period T: hysteresis Σ_reversals ½·k_h·(ΔB/2)^α·(1 + k_dc·B_dc²) / T; classical σd²/(12ρ_m)·⟨(dB/dt)²⟩; excess k_e·C·⟨|dB/dt|^1.5⟩ with C such that a sinusoid gives k_e·(fB)^1.5 (C = (2π)^-1.5 / ⟨|cos x|^1.5⟩ ≈ 0.1323).
- Default stroke angles 60 per rotor pole pitch, snapped to the band pitch; convergence limit < 2 % at 120.
- Default efficiency grid 6 speeds × 5 torque levels. Speeds `linspace(max_speed/6, max_speed, 6)`; torque levels k/5 · envelope torque at that speed, k = 1..5.
- Winding temperature default 120 °C, field `Requirements.winding_temperature_c` (ruling: on `Requirements`, not `CaseInputs`, so the search and the case use one value; setup files carry it inside the requirements, no setup version bump, as in the R2 rulings).
- Loss-data grade allowance: A 0 %, B 10 %, C 25 % (provisional). Iron uncertainty = fit error + grade allowance + measured angle-convergence change, summed (worst case).
- Chips: "Winding 120 °C" (the actual value), "Excludes friction and windage", "Unvalidated".
- Versions: srmcore, srmapp, srmweb, `web/` all `0.6.0`. `VALIDATED_VERSIONS` unchanged.
- Comments describe code as it is, never task history. Test file basenames unique. No blue in `web/src`.
- Model rules for subagents: Sonnet implementers, Opus task reviewers and final review, Haiku only for log/test-output summaries.

## Review Focus

1. A case whose stator or rotor material has no `loss` block: the losses job is refused at submit with 422 naming the material, not after an hour (Task 8 `test_losses_refused_without_loss_data`).
2. An operating point the drive cannot reach at a torque level (rounding at the envelope edge): the point is reported as unreachable, the rest of the map still completes (Task 7 `test_unreachable_point_is_skipped`).
3. A non-converged solve inside a stroke: the stroke fails with the angle named, the job fails cleanly, nothing half-written in the stroke cache (Task 4 `test_failed_point_writes_no_cache`).
4. Evaluations stored before 0.6.0 (no tail, 100 °C copper): they still load, and the case page says which srmapp version made them (Task 8 `test_old_evaluation_loads`).
5. Density mode (no wire): copper AC is absent, the UI says "AC not computed (no wire chosen)" rather than showing 0 W (Task 6 `test_density_mode_skips_ac`, Task 9 vitest "density mode").

  - `reversals(b: np.ndarray, band: float) -> list[tuple[float, float]]`: (ΔB, B_dc) per half-cycle of a periodic 1-D waveform; swings below `band` are merged (rainflow-style pairing on the periodic signal starting at the global extremum).
  - `ElementLoss` frozen dataclass: `hysteresis, classical, excess` arrays (W/kg per element), `beyond_fit_range: bool`.
  - `waveform_loss(b: np.ndarray, centroids: np.ndarray, period_s: float, model: LossModel) -> ElementLoss`: `b` shape (n_t, n_el, 2) uniform in time over one period, already in each element's own frame; `centroids` (n_el, 2) in the same frame; components are radial and tangential about the origin, losses summed over the two components.

- [ ] **Step 1: Failing tests**
  - `test_sinusoid_matches_model`: B_r = B̂ sin(2πft) at (B̂, f) of every data point gives `model.sinusoid(B̂, f)` within 1 %.
  - `test_minor_loop_adds_loss`: a sinusoid plus a small 5th-harmonic loop has more hysteresis than the sinusoid alone.
  - `test_dc_bias_raises_hysteresis`: same ΔB with B_dc = 1 T > B_dc = 0.
  - `test_constant_field_no_dynamic_loss`: constant B gives classical = excess = hysteresis = 0.
  - `test_classical_scales_f_squared`: doubling f (same shape) gives 4× classical, 2^1.5× excess.
  - `test_beyond_fit_range`: a fundamental above `frequency_range[1]` sets the flag.
  - `test_rotation_frame`: a field that is purely radial in the element's frame gives zero tangential contribution.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement (pure numpy, `np.gradient` with periodic central differences). **Step 4:** Run → PASS, plus `tests/test_import_rules.py`.
