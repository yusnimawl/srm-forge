# R5e gate V4 (Kiyota 2014 peak) Implementation Plan, with the 10JNEX900 specific heat and the V5 probe note

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the 10JNEX900 specific heat to the library, so iron has heat capacity in the rating's thermal network.
Then run gate V4: the rating's thermal network on the Kiyota 18/12 with natural cooling, the Fig. 8 current trace
and the measured resistance, against the measured coil-end rise. Record the verdict and put the result into the
`end_winding_model` budget row (spec §7). Record the thermal-mesh probe of 2026-11-26 as a note for the
`thermal_mesh` row. V5 is not a separate gate (owner, 2026-11-27).

**Architecture:** the 10JNEX900 material file gets `thermal.specific_heat` = 438 J/(kg K); `build_network` already
reads it. A test-side helper `tests/kiyota_thermal.py` builds the Kiyota network with the rating's own code
(`thermal_domain`, `coefficients`, `build_network`, `PointHeat`, `load_fn`) and steps the Fig. 8 current trace
through one `ThermalSolver.transient` call. `examples/kiyota_thermal_check.py` runs V4 and writes
`docs/validation/r5_v4_kiyota.json`. No EM solve runs in V4. srmcore code does not change and its version stays
0.8.0. srmapp goes to 0.10.1 (Task 2), or to 0.11.0 if Task 7 runs.

**Tech Stack:** Python 3.12+, numpy, scipy.

**Spec:** `docs/superpowers/specs/2026-11-05-r5-thermal-stress-design.md` §7 (rows `end_winding_model`,
`thermal_mesh`), §8 gate V4, §14 (V4 is a weak check of cooling). Inputs: `docs/r5-sources.md` §9.2 and §9.3.
Scope: roadmap §0, Bike motor v1 part 2 ("Peak-heat check V4 against Kiyota 2014, with the 10JNEX900 specific heat
438 J/(kg K). The separate thermal mesh check V5 is dropped."). The V2 gap is accepted; V6 on the Kiyota rotor is
replaced by part 8.

## Findings from the diagnosis (2026-11-26 and 2026-11-27, inline prototype)

Prototype scripts in `/tmp/v4v5/` (not committed): `proto*.py` (V4), `v5proto.py` (thermal mesh), `meshsize.py`,

stator iron, 30 % in the rotor iron, uniform per unit volume.

1. **V4 is a check of adiabatic copper heating.** The Fig. 8 hold is 140.7 A RMS in 9 parallel 0.9 mm strands, so
   J = 24.6 A/mm². The integral of I² dt over the V0 trace is 11.12 s x 140.7². DC copper heating with no heat
   flow, from 51.1 degC, with the library copper (8890 kg/m3, 385.2 J/(kg K), 1.7241e-8 Ohm m at 20 degC,
   0.00393 1/K), gives 40.56 K at 14 s. The measured rise is 39.5 +- 0.4 K (trace) and
   41 K (printed). This needs no model input except the cited wire data.
2. **Our network with the measured resistance gives 42.66 K** (end-lump peak, copper only, zero iron capacity,
   `screening` and `full` the same to 0.01 K, steps of 0.05 s and 0.025 s the same to 0.01 K). The 5.2 % above item 1
   follows from the ratio (5.6 %) of the measured 97.8 mOhm to the resistance of our mean turn length (92.6 mOhm at
   20 degC, mean turn 256.3 mm). The measured value implies 271.3 mm. Kiyota's own prediction is 91.7 mOhm. The
   measured value most likely includes the leads (an inference).
3. **The sensor lags.** Measured rise 22.7 K at 10 s and 35.5 K at 14 s, ours 32.8 K and 42.7 K. The measured trace
   keeps rising for 4 s after the current stops. The paper does not give the sensor type or position. So only the
   peak rise can be compared. Time-matched values are reported, not judged.

## Calls made in this plan (not in the spec)

1. **Iron at the Fig. 8 point from the measurement.** Spec V4 says "losses from our R3 model at the Fig. 8 point".
   Since PR #44 the drive model has a stroke there, but the R3 model reads 9.75 x below the measurement at
   Table III (b) (finding 6). `K_IRON_HI` is defined on this machine as measured "iron and other" over the model
   (docs/r3-loss-results.md), so the rating's nominal iron at 1.5 kHz is about M / 3.2 and its rated iron is M,
   where M is the measured "iron and other". V4 uses that: nominal iron = M / `k_iron_hi`(1500 Hz), and
   `coefficients` applies the factor in the rated set. M = 4.4 kW, Table III (b) (130 A RMS, the measured point
   nearest the test current, 8700 r/min, which the text calls 7500 r/min). Input row: M = 0.6 kW, Table III (c)
   (7500 r/min, light load). The iron goes into the stator iron, uniform per unit volume (the rotor is behind the
   air gap, so this is the hot side for the coil. This is an assumption).
2. **Compared quantity: the end-lump peak rise.** The sensor is on the coil end (2014 p. 5716), so ours is the
   hottest end-winding lump. Ours = its maximum over 0 to 20 s minus the start temperature. The rating's hot spot
   (coil sides included) is reported beside it and not judged (nothing was measured in the slot).
3. **Target: 39.5 +- 0.4 K**, the trace reading (docs/r5-sources.md §9.2: the figure's own arrow spans 39.7 K). The
   printed 41 K gets its own verdict line beside it.
4. **Start state:** uniform 51.1 degC (the Fig. 8 start reading) at every node and free lump. Input row: copper
   nodes and end lumps at 51.1 degC, everything else at the ambient (the cold-iron start; it matters now that iron
   has capacity).
5. **Ambient 25 degC** (not printed, an assumption). Input row: 40 degC.
6. **Mechanical loss:** the measured 573 W at 7493 r/min (Fig. 7) as windage in the rotor iron (`PointHeat.windage_w`).
   The rated set takes x 1.2 (the paper's 20 % bearing-condition scatter). Input row: the same 573 W as bearing
   friction at the end caps (`PointHeat.friction_w`).
7. **The `em_torque` row has no effect in V4:** the current is imposed, not found from a torque. State it in the JSON.
8. **Band and pass rule** (spec: "measured 41 K inside our predicted band", and "the band includes input rows ...
   each from a perturbation run"): low = nominal + the sum of the negative row changes - numerical error, high =
   rated + the sum of the positive row changes + numerical error. Numerical error = |full - reference| +
   |dt - dt/2| on `full`. Pass when low - 0.4 <= 39.5 <= high + 0.4. Rows are the worst-case stack, as in spec §7.
9. **Residual into the `end_winding_model` row:** r = (39.5 - nominal) / nominal on the end-lump peak rise. If
   r <= 0 the model reads hot (the safe side), the row stays 0 and its note states the hot-side residual. If r > 0,
   Task 7 runs.
10. **Iron capacity from the library (owner, 2026-11-27).** V4's nominal and rated sets use the library value,
    438 J/(kg K) x the 10JNEX900 density 7490 kg/m3. Zero capacity is not an input row; finding 4 records its
    effect. The Faiz density 7650 kg/m3 is not used: the specific heat is carried over, the density is the
    10JNEX900 value.
11. **Thermal mesh row from the probe (owner, 2026-11-27).** e_p = the largest |p - reference| of finding 7, for
    p = `screening` (0.26 K) and `full` (0.16 K). Both are under `TOL_K` (0.5 K), so the row stays 0 and its note
    states e_p. The reference has an error of its own (P1, about 1/8 of the `full` error if the error scales with
    h², an inference), so e_p reads slightly low. The probe ran on the 8/6 only and with zero iron capacity (steady
    values do not depend on capacity; the peak values do). The note says so. The Kiyota mesh change was not run.

## Expected V4 outcome

From finding 4 (bold rows, `screening`, measured resistance, iron capacity from the library):

- Nominal end-lump peak rise 41.60 K. Rated 42.22 K.
- Against the trace reading 39.5 +- 0.4 K: the nominal reads 2.1 K (5.0 %) hot. r = (39.5 - 41.60) / 41.60 =
  -0.050, so the `end_winding_model` row stays 0 and Task 7 does not run (Call 9).
- Against the printed 41 K: the nominal reads 0.6 K (1.4 %) hot, r = -0.014.
- Pass rule (Call 8) for 39.5 K: pass when low <= 39.9 K, that is, the negative row changes plus the numerical
  error reach at least 1.7 K below the nominal. The resistance row (92.6 instead of 97.8 mOhm, -5.3 % on the copper
  heat) is expected to give about -2.2 K (41.60 x 92.6 / 97.8 = 39.4 K; an inference from finding 2, where the
  copper term sets the peak). The cold-iron start row also lowers it. So V4 is expected to pass, and only through
  these rows. Without them the band would sit 1.7 K above the measurement. The upper side holds with margin
  (39.5 < 42.22 + 0.4).
- Pass rule for 41 K: pass when low <= 41.4 K (0.2 K of negative rows); expected to pass.
- If the full run disagrees (low above 39.9 K), V4 fails on the hot side. The verdict records it. The row still
  stays 0 because r <= 0.
